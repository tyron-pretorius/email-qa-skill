# Brand & tone guidelines (distilled for email QA)

> Source: example guidelines for the fictional company "Acme". Replace this file with your own
> messaging framework and language rules.

## Language rules — always enforce

| Say | Never say |
|-----|-----------|
| customer data platform | data tool, database software |
| enterprise-ready, secure by default | cheap, basic |
| AI-assisted workflows | AI-powered magic, robots do it for you |

## Approved phrases and usage scope

- "Built for teams. Ready for scale." — for event and community contexts (conferences, user groups)
- "Your data, working harder." — closing line or tagline
- "Customer data platform" — everyday descriptor
- "Customer data system" — hero-level and enterprise sales contexts only

## Positioning rules

- Never lead with individual features (dashboards, exports) in hero copy — it undermines the platform positioning.
- Flag immediately any drift toward old language (the "never say" column above).

## QA application

When checking email copy: quote any violating sentence, name the rule, and propose a compliant rewrite. Treat "never say" terms as blocking failures; scope misuse (e.g. "data system" in everyday copy) as warnings.
